# RB-08: the opponent's yards before contact allowed and its box on runs (pre-registered 2026-11-02)

**Status: PRE-REGISTERED.** Written before any score was seen; the only runs
before this were `--coverage-only` (coverage and the leak check, no score).

## Idea
Roadmap RB-08, "Opponent yards before contact and box counts allowed", from
PFR advanced rushing (team sums) and FTN charting's `n_defense_box`. The
shipped RB set already carries `def_allowed` (the fantasy points the
opponent allowed to running backs per game this season, minus the league),
the implied team total (the market's price of the matchup) and the back's
own volume and efficiency (`xfp_*`, `carries_l3`, `fpoe_season`,
`ngs_ryoe`). FEATURE_EXPANSION's `+pfr` (the back's OWN yards before and
after contact) and `+ngs2` (his stacked-box rate) failed; both were about
the back. This is the defense's side, which neither tested.

## Hypothesis
Fantasy points allowed mix run defense with touchdowns and game script, so
they are noisy. Yards before contact allowed per running-back carry measure
how much room a defense's front gives, and a defense that shows light boxes
on runs gives more of it. Backs facing such a defense gain more per carry
than `def_allowed` alone says. This is the opponent's efficiency, so it
enters only as a slow prior (rule #6): season to date, relative to the
league over the same weeks.

## Features (`COLUMNS`)
| column | position(s) | definition, as of the weeks before the row's week | source |
|---|---|---|---|
| `opp_ybc_allowed_std` | RB | the opponent's rushing yards before contact allowed per carry to running backs (box-score position RB or FB in that game) in its games this season, minus the league's per-carry figure over the same weeks | PFR advanced rushing, weekly (`rushing_yards_before_contact`, `carries`), summed by the team the rusher faced; crosswalk pfr -> gsis (rule #3); player box scores |
| `opp_box_std` | RB | the average defenders in the box (`n_defense_box`) the opponent showed on the designed runs it faced this season (`play_type == "run"`; scrambles, two-point tries and boxes charted 0 excluded), minus the league's average over the same weeks | FTN charting joined to play-by-play on (`game_id`, `play_id`) |

Missing when: `opp_ybc_allowed_std` has a value on every scored row (every
defense has played by week 4); `opp_box_std` is missing on every row of
2019-2021 (FTN starts in 2022). Missing enters as 0 plus `<col>__known`.

Shared code: `scripts/research/blocks/_p1b_ftn_pfr_opponent.py`
(`back_rushes`, `ftn_plays`, `league_as_of`). The runner's Context has no
PFR loader; `pfr_rush` loads PFR's weekly rushing through the Context's
frame store under the post-game `weekly` classification, so the leak check
cuts it like every other post-game frame (checked: a variant that reads the
row's own week is flagged). The helper maps team codes itself (PFR writes
OAK in 2018-2019; the runner's `normalize_teams` does not rewrite pandas 3
string columns). Running backs carry 11,190-11,873 times a season in
2019-2025; the league figure moves from 2.07 (2019) to 2.58 (2022) yards
before contact per carry, which is why both columns are relative to the
league. FTN charts a box on 99.6-99.9% of designed runs.
